# Add-on: ask, don't guess (T05 rule 9)

Append this paragraph to any product-video prompt.

- For every feature you show, the problem it solves and why it matters must come from the product's documents or from the owner's answer. If the documents only say what a feature does, say only that; do not invent a pain point for it.
- Choose which features to feature by the documents' own emphasis (for example a "core features" list). If the documents give no order, or contradict each other or the running product, that is a question for the owner.
- If you can ask the owner, ask before you build. If you cannot (an unattended run), write `build/questions.md`, one entry per question: the feature, what the documents say, what is missing, and the question. Then describe the feature plainly, as documented.
